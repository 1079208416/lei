# 外卖平台 MVP 产品设计文档

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | 外卖平台 MVP |
| 产品类型 | 单城市、多商户、平台型外卖 |
| 文档版本 | V1.0 |
| 文档状态 | 初稿 |
| 目标阶段 | 首批真实用户和商户试点 |

## 2. 产品方向

### 2.1 产品定位

面向单一城市或单一运营区域，连接用户、商户和配送人员，提供附近商家浏览、在线点餐、在线支付、商家接单、人工派单和配送跟踪服务。

### 2.2 MVP 目标

- 跑通从用户下单到订单完成的全流程。
- 验证用户是否愿意下单并有复购需求。
- 验证商户能否稳定接单、出餐和处理异常。
- 验证配送成本、配送时效和运营效率。
- 用少量真实商户和真实订单跑通业务，不追求平台规模。

### 2.3 MVP 成功指标

- 订单支付成功率和订单完成率。
- 商户平均接单时间。
- 从支付到送达的平均时长。
- 订单取消率、退款率和缺货率。
- 配送成本占订单金额比例。
- 用户首单后 7 天复购率。
- 试点商户的日均有效订单数。

### 2.4 产品形态建议

- 用户端：微信小程序或移动端 H5。
- 商家端：移动端优先的 H5 或轻量应用，方便随时接单。
- 骑手端：移动端 H5，优先保证订单状态操作。
- 平台后台：Web 管理后台。

## 3. 用户角色

| 角色 | 核心诉求 |
| --- | --- |
| 用户 | 找到附近商家，快速点餐、支付、查看配送进度和处理售后 |
| 商户 | 维护店铺和菜单，及时接单、出餐并处理异常 |
| 骑手 | 接收配送任务，查看取送信息并更新配送状态 |
| 平台运营 | 审核商户、监控订单、人工派单、处理退款和配置运营规则 |
| 平台客服 | 查询订单、联系用户或商户、处理取消和退款 |

## 4. MVP 范围

### 4.1 首版必须包含

- 单一城市或单一运营区域。
- 附近商家和商家菜单浏览。
- 单商户购物车和即时配送订单。
- 在线支付。
- 商户接单、拒单和出餐状态处理。
- 平台人工派单。
- 骑手取餐和送达状态处理。
- 用户订单查询和配送状态查看。
- 取消、退款和客服处理。
- 商户、商品、订单、配送和基础运营数据管理。

### 4.2 首版明确不做

- 多城市和多区域独立运营。
- 复杂搜索、推荐和广告排序。
- 优惠券、满减、会员、积分和钱包。
- 预约单、定时达和跨天订单。
- 多商户合并购物车。
- 智能派单、骑手抢单和路径规划。
- 实时地图轨迹和复杂配送调度。
- 用户评价、内容社区和社交功能。
- 商家在线结算和自动分账。
- 复杂售后、部分退款和商品级退款。
- 发票、企业采购和月结。

## 5. 核心业务流程

### 5.1 正常下单流程

1. 用户授权定位或手动选择收货地址。
2. 用户浏览附近商家、分类、菜单和商品规格。
3. 用户将商品加入购物车并提交订单。
4. 用户确认地址、联系人、备注、配送费和预计送达时间。
5. 用户完成在线支付。
6. 订单进入商户待接单状态。
7. 商户接单并开始制作。
8. 商户出餐后，平台运营为订单分配骑手。
9. 骑手确认取餐并开始配送。
10. 骑手确认送达，订单完成。
11. 用户在订单详情中查看状态和历史订单。

### 5.2 异常处理流程

- 未支付订单超时后自动取消。
- 商户超时未接单时，系统提醒运营介入。
- 商户拒单或商品缺货时，订单取消并原路退款。
- 商户接单前，用户可直接取消；接单后需发起售后申请。
- 骑手无法联系用户或无法完成配送时，上报平台客服处理。
- 订单取消或退款后，同步关闭对应配送任务。

## 6. 功能设计

### 6.1 用户端

#### 账号与基础信息

- 手机号验证码登录。
- 查看和编辑个人资料。
- 查看用户协议、隐私政策和客服入口。

#### 定位与地址

- 获取当前位置。
- 手动选择配送地址。
- 新增、编辑和删除收货地址。
- 保存联系人、手机号和门牌号。
- 设置默认地址。
- 根据地址判断是否在配送范围内。

#### 首页与商家发现

- 展示当前配送地址。
- 展示附近可营业商家。
- 按餐饮分类筛选商家。
- 按商家名称或菜品名称进行简单搜索。
- 展示商家距离、起送价、配送费、预计送达时间和营业状态。
- 展示基础公告或运营位，首版不做复杂个性化推荐。

#### 商家与商品

- 查看商家名称、图片、地址、营业时间、公告和配送信息。
- 按分类查看菜单。
- 查看商品图片、名称、描述、价格、规格和加料。
- 选择商品规格、数量和备注。
- 展示售罄商品并禁止加入购物车。
- 查看购物车商品数量和金额。

#### 购物车与结算

- 同一订单仅支持一个商家。
- 增加、减少和删除购物车商品。
- 计算商品金额、打包费和配送费。
- 校验起送价、营业状态、配送范围和商品库存。
- 选择收货地址和联系人。
- 填写订单备注。
- 确认预计送达时间。
- 提交订单并发起在线支付。
- 支付成功、失败和取消结果反馈。

#### 订单与配送

- 查看待支付、进行中、已完成和已取消订单。
- 查看订单商品、金额、地址和支付信息。
- 查看商家接单、制作、待取餐、配送中和已完成状态。
- 查看骑手姓名、联系电话和预计送达时间。
- 联系商户或平台客服。
- 未接单时取消订单。
- 接单后发起整单退款申请。
- 对已取消或已退款订单查看处理结果。
- 对历史订单再次下单。

#### 消息与售后

- 接收支付、接单、配送和退款状态通知。
- 查看售后处理进度。
- 提交异常订单说明和联系方式。

### 6.2 商家端

#### 账号与店铺

- 商家账号登录。
- 查看和编辑店铺基础信息。
- 设置营业时间、店铺公告和联系电话。
- 开启或暂停接单。

#### 菜单管理

- 新增、编辑、删除和排序商品分类。
- 新增、编辑、上架和下架商品。
- 设置商品名称、图片、描述、价格和打包费。
- 设置商品规格、加料和对应价格。
- 设置商品库存或标记售罄。
- 调整商品在分类中的展示顺序。

#### 订单处理

- 接收新订单通知和声音提醒。
- 查看订单商品、规格、备注、收货信息和金额。
- 接单或拒单。
- 填写预计出餐时间。
- 将订单标记为制作中和待取餐。
- 联系用户或平台运营。
- 处理缺货、退款和异常订单。
- 查看当日和历史订单。

#### 基础经营数据

- 查看当日订单数、成交金额、取消订单数和退款订单数。
- 查看商品销售数量排行。

### 6.3 骑手端

#### 账号与任务

- 骑手账号登录。
- 查看平台分配的待取餐、配送中和已完成任务。
- 查看任务详情和联系信息。

#### 配送处理

- 查看商户取餐地址、用户收货地址和订单备注。
- 一键调用第三方地图导航。
- 联系商户或用户。
- 确认取餐并开始配送。
- 确认送达并完成订单。
- 上报联系不上用户、地址异常等配送问题。
- 查看历史配送记录。

### 6.4 平台管理后台

#### 数据概览

- 查看当日订单数、成交金额、完成率、取消率和退款率。
- 查看待接单、待派单、配送中和异常订单数量。

#### 商户管理

- 创建和审核商户。
- 查看商户资料和经营状态。
- 启用、暂停或关闭商户。
- 查看和检查商户菜单、商品和营业配置。
- 配置商户配送范围和基础规则。

#### 用户管理

- 查询用户和收货地址。
- 查看用户订单记录。
- 处理用户投诉和账号异常。

#### 订单管理

- 按订单号、用户、商户、配送状态和时间查询订单。
- 查看完整订单详情和状态流转记录。
- 处理取消、拒单、退款和配送异常。
- 对异常订单添加内部备注。

#### 配送管理

- 查看待派单、配送中和异常任务。
- 人工分配、改派和取消骑手任务。
- 查看骑手工作状态和历史配送记录。
- 配置配送区域、配送费规则和预计送达时间。

#### 售后管理

- 查看退款和异常订单。
- 审核并执行整单退款。
- 记录客服处理结果。
- 关闭已完成的售后单。

#### 运营配置

- 管理基础商家分类和商品分类。
- 配置首页基础运营位。
- 配置未支付取消时长、商户接单提醒阈值等基础参数。
- 查看基础运营报表。

#### 权限与日志

- 区分超级管理员、运营和客服角色。
- 记录退款、取消、派单和商户状态变更等关键操作日志。

## 7. 订单状态

| 状态 | 说明 | 可执行角色 |
| --- | --- | --- |
| 待支付 | 订单已创建，尚未完成支付 | 用户支付、系统超时取消 |
| 待接单 | 支付成功，等待商户处理 | 商户接单或拒单、用户申请取消 |
| 制作中 | 商户已接单并开始制作 | 商户标记待取餐 |
| 待取餐 | 商户已出餐，等待骑手取餐 | 平台派单、骑手确认取餐 |
| 配送中 | 骑手已取餐并送往用户 | 骑手确认送达、上报异常 |
| 已完成 | 用户已收到订单 | 用户申请售后、平台处理售后 |
| 已取消 | 订单在完成前取消 | 用户、商户、平台查看 |
| 退款中 | 订单进入退款处理 | 平台审核和处理 |
| 已退款 | 退款已完成 | 各方查看结果 |

## 8. 核心业务规则

- 一个订单只能包含一个商户的商品。
- 首版只支持立即配送，不支持预约配送。
- 商品价格和规格信息在下单时生成快照，后续商户改价不影响已创建订单。
- 下单前校验商户营业状态、配送范围、起送价和商品可售状态。
- 支付成功后才通知商户接单。
- 商户拒单、缺货或平台取消订单时，默认执行整单退款。
- 未支付订单超过配置时长后自动取消。
- 商户长时间未接单时，系统提醒运营介入。
- 首版仅支持整单退款，不支持商品级部分退款。
- 用户完成支付后，如商户已接单，取消订单需经商户或平台确认。
- 订单进入配送中后，原则上不允许直接取消，由平台客服处理。
- 首版由平台人工派单，不建设智能调度和骑手抢单。
- 商家结算在 MVP 阶段可在线下完成，系统只提供订单和金额统计。

## 9. 核心数据对象

| 对象 | 主要内容 |
| --- | --- |
| 用户 | 账号、手机号、状态和创建时间 |
| 收货地址 | 联系人、手机号、地址、经纬度和默认状态 |
| 商户 | 店铺资料、营业信息、配送范围和经营状态 |
| 商品分类 | 分类名称、排序和状态 |
| 商品 | 名称、图片、价格、规格、库存和上下架状态 |
| 购物车 | 用户、商户、商品、规格和数量 |
| 订单 | 用户、商户、地址、金额、状态和时间信息 |
| 订单明细 | 商品、规格、数量、单价和金额快照 |
| 支付记录 | 支付渠道、金额、状态和交易号 |
| 配送任务 | 订单、骑手、取送地址、配送状态和时间 |
| 售后单 | 订单、原因、处理状态和退款结果 |
| 操作日志 | 操作人、操作对象、操作类型和时间 |

## 10. MVP 验收标准

- 用户能够完成登录、添加地址、选择商家、添加商品、提交订单和在线支付。
- 商户能够收到新订单，并完成接单、拒单、制作和出餐操作。
- 平台能够对待取餐订单进行人工派单和改派。
- 骑手能够完成取餐、配送和送达操作。
- 用户能够查看订单状态、联系骑手或商户，并完成取消或退款申请。
- 平台能够处理退款、异常订单和关键运营配置。
- 支付失败、商户拒单、商品缺货和配送异常均有明确处理结果。
- 各角色只能看到与自身相关的订单和数据。
- 关键操作具备状态记录和操作日志。

## 11. 试点与迭代方向

### 试点阶段

- 选择单一区域和 3 至 10 家真实商户。
- 由平台人工控制商家供给、派单和客服。
- 优先观察真实订单完成情况和异常比例。
- 控制每日订单量，确保问题能够被人工跟进。

### 试点后优先迭代

- 根据订单数据补充高频商品、商家分类和搜索能力。
- 优化商户接单、出餐和派单流程。
- 增加用户评价或满意度反馈。
- 增加优惠券和满减等基础营销工具。
- 逐步建设骑手调度、商家结算和更完整的经营分析。

## 12. 总结

MVP 的核心不是功能数量，而是形成可运营的完整闭环：用户愿意下单，商户能够稳定履约，骑手能够完成配送，平台能够处理支付、退款和异常。首版应优先保证交易流程、订单状态和异常处理可靠，再根据试点数据扩充营销、评价、调度和结算能力。
